# Contributing

- **Fix a playbook:** open a pull request and say what was wrong.
- **Add a playbook:** copy an existing one and keep the order: problem, systems, how it splits, job description, approval gate, build prompt.
- Every write needs an approval step or a reason it does not.
- Describe patterns, not results. Do not add outcome numbers you cannot source.
- Use "two-way sync". Describe restrictions as read-only access or write permissions.
- Never include real credentials, customer data or internal URLs.
